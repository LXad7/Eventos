1. Registos e instruções básicas

  • 32 registos inteiros de 64 bits: r0 … r31. r0 vale sempre 0 (escrever nele não faz nada).
  • r31 guarda o endereço de retorno do jal. r29 costuma ser o ponteiro da pilha.
  • Instruções começadas por d trabalham com 64 bits (doubleword): dadd, daddi, dsub, dmul.
InstruçãoFaz
daddi r1,r2,100r1 = r2 + 100 (imediato de 16 bits com sinal: −32768 … 32767)
daddi r1,r0,5r1 = 5 (é assim que se põe uma constante num registo)
daddi r4,r0,Msgr4 = endereço da etiqueta Msg (não o conteúdo!)
dadd r1,r2,r3 / dsubr1 = r2 + r3 / r1 = r2 − r3
dmul r1,r2,r3r1 = r2 × r3
slt r1,r2,r3se r2 < r3 então r1 = 1, senão r1 = 0
slti r1,r2,20se r2 < 20 então r1 = 1, senão r1 = 0
and/or/xor r1,r2,r3operação lógica bit a bit entre registos
andi/ori/xori r1,r2,immoperação lógica com imediato de 16 bits (preenchido com zeros à esquerda)
dsll / dsrl r1,r2,ndesloca n bits para a esquerda (×2ⁿ) / direita (÷2ⁿ)
halttermina o programa
Exemplo (P11 do treino): daddi r1,r0,1 · daddi r2,r0,2 · daddi r3,r0,3 · slt r1,r3,r2 → 3 < 2 é falso, logo r1 = 0. Final: r0=0, r1=0, r2=2, r3=3.

O programa tem duas partes: .data (variáveis) e .code / .text (instruções).

3. Como a memória fica arrumada (janela Data)

  1. Cada linha de diretiva começa num endereço múltiplo de 8. Se a anterior não acabou num múltiplo de 8, o resto fica vazio.
  2. Os valores dentro da mesma diretiva ficam seguidos (juntos).
  3. O MIPS é little endian: o byte menos significativo fica no endereço mais baixo.
  4. A janela Data mostra 8 bytes por linha, lidos da direita para a esquerda (o byte do endereço mais baixo está à direita).
.data
Text: .asciiz "Arquitectura"   ; 13 bytes: endereços 0..12
CR:   .word32 0x10000          ; próximo múltiplo de 8 → endereço 16 (0x10)
DR:   .word32 0x10008          ; endereço 24 (0x18)

Ler um vetor de .word16 na janela Data (P12 do treino)

0010 00070064000f0003   V: .word16 3, 15, 100, 7, 0xf5aa, 17, 5, 15, -100, 2023
0018 000f00050011f5aa
0020 0000000007e7ff9c

Na linha 0x10, partindo da direita, em grupos de 4 dígitos hex (2 bytes): 0003=V[0]=3, 000f=V[1]=15, 0064=V[2]=100, 0007=V[3]=7. Na linha 0x18: f5aa=V[4], 0011=V[5]=17 … Na linha 0x20: ff9c=−100 e 07e7=2023.

Endereço do elemento: endereço(V[i]) = endereço(V) + i × tamanho. Ex.: V em 0x10, .word16 → V[3] está em 0x10 + 3×2 = 0x16 (22).

Little endian com .byte (Ex. 7b1)

Para guardar o IP 192.168.10.15 de modo que, lido como 32 bits, dê 0xC0A80A0F, declara-se ao contrário: IP: .byte 15,10,168,192 (o 15 fica no endereço 0, o 192 no endereço 3). Equivalente: IP: .word32 0xC0A80A0F.

No Ex. 8b, os 10 valores .word16 devem estar todos na mesma linha (ou 4 por linha = 8 bytes), senão cada nova linha salta para o próximo múltiplo de 8 e o vetor fica com buracos.

4. Load / Store e endereçamento

Ler (memória → registo)Escrever (registo → memória)Bytes
ldsd8 (.word)
lw (com sinal) / lwu (sem sinal)sw4 (.word32)
lh / lhush2 (.word16)
lb / lbusb1 (.byte, caracteres)

Formato: ld r1, Etiqueta(rX) → lê do endereço Etiqueta + rX.

  • ld r1, A(r0) → lê a variável A (r0 = 0).
  • ld r1, V(r8) → lê de V + r8 (r8 = deslocamento em bytes).
  • ld r1, (r2) → lê do endereço guardado em r2.
  • sd r4, s(r5) → escreve r4 em s + r5.
P6/P9 do treino: daddi r4,r0,16 · daddi r5,r0,8 · sd r4,s(r5) com s um vetor de .word (8 bytes): deslocamento 8 bytes ÷ 8 = índice 1 (o 2.º elemento). Valor enviado para a memória: 16.
Deslocamento ≠ índice. O valor dentro dos parênteses é em bytes. Para o índice i: deslocamento = i × tamanho do elemento (8 para .word, 4 para .word32, 2 para .word16, 1 para .byte).

lw vs lwu: lw estende o sinal (se o bit 31 for 1, os 32 bits de cima ficam a 1); lwu enche com zeros. O mesmo para lb/lbu: o byte 200 (0xC8) lido com lb dá −56; com lbu dá 200. Para CR e DR usa-se lwu.

5. Vetores (Ex. 8)

Regra: Vetor[i] em C = Vetor(i × tamanho) em MIPS.

.data
Vetor: .word 3, 15, 100, 7, 0xF9876543987625aa
       .word 17, 5, 15, -100, 2023      ; 10 inteiros de 64 bits = 80 bytes
VLen:  .word 10
CR:    .word32 0x10000
DR:    .word32 0x10008
.code
       lwu r2,DR(r0)
       lwu r1,CR(r0)
       ld r10,VLen(r0)       ; r10 = tamanho
       daddi r5,r0,0         ; i = 0
For:   slt r3,r5,r10         ; i < VLen ?
       beqz r3,FimFor        ; se não, sai
       daddi r3,r0,8         ; 8 bytes por elemento
       dmul r8,r5,r3         ; r8 = i*8
       ld r4,Vetor(r8)       ; r4 = Vetor[i]
       sd r4,(r2)            ; DATA = r4
       daddi r3,r0,2         ; código 2 = inteiro com sinal
       sd r3,(r1)            ; CONTROL = 2 → mostra
       daddi r5,r5,1         ; i++
       j For
FimFor:
; Somar 1 ao 4.º elemento (índice 3 → byte 24)
       daddi r5,r0,3
       daddi r3,r0,8
       dmul r8,r5,r3         ; r8 = 24
       ld r4,Vetor(r8)
       daddi r4,r4,1
       sd r4,Vetor(r8)
       halt

Ex. 8b (inteiros de 16 bits): só mudam 3 coisas: .word16 na declaração, 2 em vez de 8 no tamanho, e lh/sh em vez de ld/sd. O 4.º elemento fica no byte 3 × 2 = 6.

"4.º elemento" = índice 3 (começa em 0). Lê sempre com atenção se a pergunta conta a partir de 0 ou de 1.

6. Entrada/Saída: CR e DR (Ex. 5)

O terminal controla-se escrevendo em dois endereços especiais: CONTROL = 0x10000 e DATA = 0x10008.

.data
CR: .word32 0x10000
DR: .word32 0x10008
.code
lwu r1,CR(r0)   ; r1 = 0x10000 (endereço do CONTROL)
lwu r2,DR(r0)   ; r2 = 0x10008 (endereço do DATA)
Código em CONTROLEfeito
1mostra DATA como inteiro sem sinal
2mostra DATA como inteiro com sinal
3mostra DATA como vírgula flutuante
4mostra a string cujo endereço está em DATA
5pixel RGB (gráficos)
6limpa o terminal
7limpa o ecrã gráfico
8lê um inteiro (ou float) do teclado para DATA
9lê um byte (carácter) para DATA, sem eco

Os 4 padrões que tens de saber de cor

; Mostrar string Msg              ; Mostrar inteiro em r4
daddi r4,r0,Msg   ; endereço         sd r4,(r2)        ; DATA = r4
sd r4,(r2)        ; DATA = end.      daddi r3,r0,2
daddi r3,r0,4                        sd r3,(r1)        ; CONTROL = 2
sd r3,(r1)        ; CONTROL = 4

; Ler inteiro para r4             ; Limpar terminal
daddi r3,r0,8                        daddi r3,r0,6
sd r3,(r1)        ; CONTROL = 8      sd r3,(r1)
ld r4,(r2)        ; r4 = DATA
Ordem: para mostrar, primeiro põe-se o valor em DATA e só depois o código em CONTROL (é a escrita em CONTROL que dispara a ação). Para ler, primeiro o código 8 em CONTROL e depois lê-se DATA.
Para mostrar string usa-se daddi r3,r0,Msg (o endereço), não ld. A string tem de ter \0 no fim (.asciiz). As strings mostradas seguidas aparecem coladas (P4: "Bom" + "Dia" = BomDia).

Atenção ao j no fim do bloco "então": sem ele, o programa continua a correr para dentro do "senão". E beq r1,r0,X com r1 = 0x10000 (endereço do CR) nunca salta (P4).

8. Operações lógicas e máscaras (Ex. 7a)

Cada bit representa uma porta (bit 0 à direita). Convenção: 0 = aberta, 1 = fechada.

Quero…OperaçãoMáscaraPorquê
pôr a 1 (fechar)OR / ori1 nos bits a mudar, 0 no restox OR 1 = 1; x OR 0 = x
pôr a 0 (abrir)AND / andi0 nos bits a mudar, 1 no restox AND 0 = 0; x AND 1 = x
inverter (trocar estado)XOR / xori1 nos bits a mudar, 0 no restox XOR 1 = não x; x XOR 0 = x

Como calcular a máscara em hexadecimal

  1. Escreve os bits das portas a mudar: portas 2 e 15 → bit 2 = 0x0004, bit 15 = 0x8000 → 0x8004.
  2. Para OR/XOR a máscara é essa: fechar portas 2 e 15 → ori r7,r7,0x8004 (P7).
  3. Para AND inverte-se tudo: abrir porta 2 em 8 bits → 1111 1011 = 0xFB → andi r1,r1,0xFB.

Ex. 7a resolvido (8 portas, estado inicial portas 0 e 5 abertas)

daddi r1,r0,0xDE   ; 1101 1110 → portas 0 e 5 abertas (a 0)
andi r1,r1,0xFB    ; abrir porta 2:  máscara 1111 1011 → 1101 1010
ori  r1,r1,0x20    ; fechar porta 5: máscara 0010 0000 → 1111 1010
xori r1,r1,0x06    ; trocar 1 e 2:   máscara 0000 0110 → 1111 1100

Máscaras com mais de 16 bits (P8)

Os imediatos de andi/ori/xori só têm 16 bits. Para mexer em bits acima do 15 (ex.: porta 19), declara-se a máscara em memória e usa-se a versão com registos:

Mask: .word32 0xFFF7FFFB   ; abrir portas 2 e 19: tudo a 1 exceto bits 2 e 19
...
lw  r8,Mask(r0)            ; lw estende o sinal: os bits de cima também ficam a 1
and r7,r7,r8

Cálculo: bit 2 = 0x4, bit 19 = 0x80000 → 0x00080004 → invertido em 32 bits = 0xFFF7FFFB.

AND precisa da máscara invertida (0 onde queres apagar). OR e XOR usam a máscara "direta". Na P1: 0x2745 XOR 0x0500 = 0x2245; 0x2245 OR 0xF000 = 0xF245.

9. Endereços IP e máscaras de rede (Ex. 7b)

  • IPv4 = 32 bits = 4 octetos. 192.168.10.15 = C0.A8.0A.0F (hex).
  • Máscara /25 = 25 bits a 1 + 7 a 0 = 255.255.255.128 = 0xFFFFFF80.
  • Endereço de rede (parte host a 0) = IP AND máscara → 192.168.10.0.
  • Broadcast (parte host a 1) = IP OR máscara invertida (0x0000007F) → 192.168.10.127.
.data
IP:       .byte 15,10,168,192      ; 192.168.10.15 em little endian
Mask_25:  .word32 0xFFFFFF80
Mask_inv: .word32 0x0000007F
.code
lw  r1,IP(r0)
lw  r8,Mask_25(r0)
and r1,r1,r8          ; rede: 192.168.10.0
lw  r8,Mask_inv(r0)
or  r1,r1,r8          ; broadcast: 192.168.10.127
/nÚltimo octeto da máscaraMáscara (hex)Invertida
/240 (0000 0000)0xFFFFFF000x000000FF
/25128 (1000 0000)0xFFFFFF800x0000007F
/26192 (1100 0000)0xFFFFFFC00x0000003F
/27224 (1110 0000)0xFFFFFFE00x0000001F
/28240 (1111 0000)0xFFFFFFF00x0000000F

As máscaras de 32 bits não cabem num imediato de 16 bits → por isso usa-se .word32 + lw + and/or (com registos).

10. Strings e ASCII (Ex. 9)

Carácter'\0'EnterEspaço'0'…'9''A'…'Z''a'…'z'
Código01332 (0x20)48…5765…9097…122
  • Cada carácter ocupa 1 byte → lê-se com lb e escreve-se com sb; o índice i é diretamente o deslocamento.
  • Maiúscula = minúscula − 32 ('a' 97 − 'A' 65 = 32).
  • Valor de um dígito = código − 48 ('7' = 55 → 7).

9a1 — contar caracteres

       daddi r4,r0,0          ; i = 0
While: lb r3,String(r4)       ; r3 = String[i]
       beqz r3,FimWhile       ; '\0' → fim
       daddi r4,r4,1          ; i++
       j While
FimWhile:                     ; r4 = n.º de caracteres

Esta é a P3 do treino: a linha em falta é lb r3,String(r4). Para "123456" dá r4 = 6.

9a2 — contar espaços

       daddi r6,r0,0x20       ; espaço
While: lb r3,String(r4)
       beqz r3,FimWhile
       bne r3,r6,NaoEspaco    ; se não é espaço, não conta
       daddi r5,r5,1          ; conta++
NaoEspaco:
       daddi r4,r4,1
       j While

9b — minúsculas para maiúsculas

While: lb r4,String(r5)
       beqz r4,FimWhile
       slti r3,r4,97          ; c < 'a' ?
       bnez r3,NaoConverte
       slti r3,r4,123         ; c <= 'z' ?  (c < 123)
       beqz r3,NaoConverte
       daddi r4,r4,-32        ; maiúscula
       sb r4,String(r5)       ; guarda na string
NaoConverte:
       daddi r5,r5,1
       j While

Para um só carácter lido do teclado: código 9 em CONTROL, lb r4,(r2), daddi r4,r4,-32, sb r4,String(r0) e mostrar com código 4.

9c — string de dígitos para inteiro ("7109" → 7109)

       daddi r6,r0,0          ; total = 0
       daddi r10,r0,10
While: lb r4,String(r5)
       beqz r4,FimWhile
       dmul r6,r6,r10         ; total *= 10
       daddi r4,r4,-48        ; valor do dígito
       dadd r6,r6,r4          ; total += dígito
       daddi r5,r5,1
       j While

Iterações: 0→7 → 71 → 710 → 7109.

Escrever sb r0,Texto(r4) põe um \0 nessa posição: a string "acaba" aí quando é mostrada. Escrever um espaço (0x20) só troca a letra (P10: "Arquitectura" com espaço no índice 7 → Arquite tura).

11. Como responder às perguntas do teste

  • "Qual o valor final de…" → faz uma tabela com os registos e atualiza linha a linha. Lembra-te que r0 é sempre 0.
  • Hexadecimal: converte para binário em grupos de 4 bits, faz AND/OR/XOR e volta a juntar.
  • Tamanhos: .word 8, .word32 4, .word16 2, .byte 1, .asciiz letras+1, .ascii letras, .space n.
  • Endereços: cada linha de diretiva começa num múltiplo de 8; endereço(V[i]) = V + i×tamanho.
  • Valor de R3 em sd R0,V(R3): é o deslocamento em bytes = índice × tamanho (não o endereço completo!).
  • Output no terminal: segue os saltos; as strings saem coladas; um \0 corta a string.
  • Instrução de máscara: escolhe AND/OR/XOR, calcula a máscara, escreve sem espaços desnecessários, ex. ori r7,r7,0x8004.
  • Mais de 16 bits: máscara em .word32, carregar com lw, aplicar com and/or/xor entre registos.

Configurar teste

Cada pergunta vale 1 valor, dividido pelas caixas que tem (como no Moodle). As respostas numéricas aceitam decimal ou hexadecimal (0x…). Nas instruções, maiúsculas/minúsculas e espaços não contam.
